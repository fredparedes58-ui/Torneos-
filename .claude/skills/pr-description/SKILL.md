# PR Description — Torneos (Cantera Hub)

Genera body de PR estructurado y con scope claro. Pedro lo lee directo desde la UI de GitHub: corto, accionable, sin paja.

## Cómo trabajar

1. **Cargar contexto:**
   - `.claude/skills/repo-conventions/SKILL.md` (para entender qué áreas existen).

2. **Identificar el diff:**
   - Si el usuario lo da explícitamente, usarlo.
   - Si no, `git diff main...HEAD` o el branch actual contra main.

3. **Clasificar los archivos cambiados por área:**
   - `src/pages/`, `src/components/` → **UI / Components**
   - `src/data/mock.ts`, `src/types/` → **Mock Data / Types**
   - `vite.config.*`, `tsconfig.*`, `postcss.config.*`, `package.json` → **Config**
   - `.design/stitch_screens/` → **Stitch Sync**
   - `vercel.json`, env templates → **Deploy / Vercel**
   - `src/hooks/`, `src/utils/` → **Lógica compartida**
   - `.github/workflows/` → **CI / Workflows**

4. **Generar descripción** según `details/structure.md`.

5. **Casos especiales** según `details/special-cases.md` (hotfixes, sync con Stitch, mocks puros, etc.).

6. **Checklist final** según `details/checklist.md`.

## Principios

- **Scope claro arriba.** Una línea que resume QUÉ cambia y POR QUÉ.
- **Marcar áreas afectadas.** Pedro escanea por categoría.
- **Sin paja.** Nada de "This PR introduces…". Verbos directos.
- **Inglés en title (commit convention).** Body en español si hace falta detalle.
- **Mencionar bloqueantes verificados.** "Build verde, deploy-sentinel OK" suma confianza.

## Qué NO hacer

- No prometer features no implementadas en este PR.
- No copiar el diff dentro del body (GitHub ya lo muestra).
- No usar PR description para discutir alternativas: eso es review.
- No firmar como "Generated by Claude" (Pedro no lo quiere).

## Output esperado

```markdown
## <Title scope: short summary>

### Qué cambia
[2-4 bullets concretos]

### Por qué
[1-2 frases]

### Áreas afectadas
- [ ] UI / Components
- [ ] Mock Data / Types
- [ ] Config
- [ ] Stitch Sync
- [ ] Deploy / Vercel
- [ ] Lógica compartida
- [ ] CI / Workflows

### Checks
- [ ] `tsc -b && vite build` verde
- [ ] Sin console.log nuevos en src/
- [ ] Bundle ≤ 500 KB
- [ ] [Otros checks contextuales]

### Notas
[Solo si hay algo no obvio: decisiones tomadas, follow-ups, regresiones potenciales]
```
